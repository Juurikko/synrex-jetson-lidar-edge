# Actual QGIS interoperability: R3

The existing Windows workstation runs **QGIS3.44.14-Solothurn**. Qualification uses
the actual `qgis-ltr-bin.exe` desktop application with an isolated profile,
`--noplugins --nocustomization --code`, real point-cloud providers, an application
window and genuine window captures. This is not static XML validation or a
Matplotlib imitation. The [application receipt](../../evidence/unet_r3_qgis_qualification.json)
and [independent sidecar/record audit](../../evidence/unet_r3_qgis_sidecar_validation.json)
record the executed scope. No system software or existing user profile is changed.

Seven unchanged PDRF8/38-byte real test outputs (862,427 points) load successfully.
Every QGIS leaf-resolution `identify` histogram exactly matches the frozen native
semantic sidecar mapped to LAS1,2,200,6,9,17,201. All seven categories are actually
present across these files, not merely listed in a legend. The new
[R3 style](../../examples/unet/fractal-classification-r3.qml) labels both semantic
IDs and LAS values,200/201 as custom and bridge17 as a projection. It changes
presentation only; RC2 style and all native outputs remain untouched.

Display selection maximizes frozen predicted class support among38-byte files,
solely to exercise viewer categories after freeze. It is not random qualitative
sampling, hyperparameter selection or evidence of improved model accuracy.
The consumed256-tile test metrics remain48.756%mIoU/60.585%macro-F1. Buildings,
vegetation and water show plausible spatial patterns in the genuine screenshots,
but visual plausibility is not independent semantic accuracy certification.
Bridge/permanent-structure errors remain in the model and are not hidden or edited.

## CRS and project

Five selected files have embedded EPSG:2154 information which matches their
original sources. Two have no CRS VLR. These are explicitly assigned **horizontal
EPSG:2154 in the viewing project only**, following the
[IGN inference configuration](https://huggingface.co/IGNF/FRACTAL-LidarHD_7cl_randlanet/blame/29e74752771e2463d0dfa64a4d0b9a4f7868d178/FRACTAL-LidarHD_7cl_randlanet-inference-Myria3DV3.8.yaml).
No coordinates, source LAZ or native classified metadata are rewritten and no
vertical datum is asserted for those missing tags. The receipt distinguishes
assignment from reading embedded CRS. An actual EPSG:4326 display transformation
and project reopening pass. The saved `.qgz` contains relative data paths, the
explicit layer CRS and classified renderer for every layer.

QGIS creates separate EPT display indices beside copied38-byte files. Its display
index order is not the source record order; the original LAZ and hash-bound
semantic sidecar remain authoritative. Independent laz-rs verification after
viewing confirms original source order, every unrelated point byte, classification
values and qualified metadata. All copied immutable inputs retain their SHA256s.

## Direct-LAZ limitation and indexed viewing path

The initial [negative trials](../../evidence/unet_r3_qgis_negative_inputs.json)
reject three48-byte files in QGIS's direct `pdal` provider with
`readers.las: Extra byte specification exceeds point length beyond base format length.`
The **same original IGN files** are rejected; this was not introduced by the
native writer. Standalone PDAL2.10.0 (`eb9126`) reads full point statistics from
the original and classified first example successfully. This narrows the observed
failure to the QGIS direct-LAZ integration path. The precise upstream cause is
not proven; no generic assertion that all48-byte inputs or all QGIS versions fail.
The original Extra Bytes descriptors, records and files are not "repaired" or
silently normalized. Direct opening of these three cases remains **FAIL**.

For those cases, R3 provides **separate COPC viewing derivatives**, generated by
the already installed PDAL writer. `tools/qgis_copc_view.py` stages the original
classified attributes plus `SynRexSourceIndex` (zero-based immutable original
record index) and `SynRexSemanticID` (full model output channel). COPC reorders
points and rewrites/indexes metadata. It is a viewing derivative, not the accepted
metadata-preserving native result and not a new native input capability.

[Independent verification](../../evidence/unet_r3_copc_independent.json) sorts
by `SynRexSourceIndex`, requires exactly one copy of every index, restores the
original structured record and compares **all original point bytes exactly**, as
well as the full semantic vector, coordinate scale and offset. COPC output hashes
are bound to the exact original classified LAZ and sidecar. The original LAZ and
its full metadata remain unchanged and shipped separately. Python/PDAL viewing
preparation is outside native neural classification, which still has no interpreter.

## Reproduction

Use the accepted native outputs and sidecars from the frozen campaign. No model
retraining, test selection, inference rerun or engine recompilation is needed:

```bash
python tools/prepare_qgis_showcase.py --data build/unet-r2/data \
  --qualified build/unet-r2/rtx/unet-r2-safe-qualified --out build/qgis-view
```

This deterministically selects seven viewer-compatible examples, validates the
source/model/output/taxonomy bindings with laz-rs, and copies exact originals,
classified results, semantic sidecars, bindings, style, model identity and notices.
Transfer that directory through the private workstation channel. Configure the
existing QGIS environment in a new `.cmd` file (avoid naming it `pdal.cmd`):

```bat
@echo off
set "QGIS_ROOT=C:\Program Files\QGIS 3.44.14"
set "SYNREX_QGIS_ROOT=%USERPROFILE%\SynRex-qgis-view"
call "%QGIS_ROOT%\bin\o4w_env.bat"
set "PATH=%QGIS_ROOT%\apps\qgis-ltr\bin;%PATH%"
set "QGIS_PREFIX_PATH=%QGIS_ROOT:\=/%/apps/qgis-ltr"
set "QT_PLUGIN_PATH=%QGIS_ROOT%\apps\qgis-ltr\qtplugins;%QGIS_ROOT%\apps\Qt5\plugins"
set "PYTHONPATH=%QGIS_ROOT%\apps\qgis-ltr\python;%PYTHONPATH%"
"%QGIS_ROOT%\bin\qgis-ltr-bin.exe" --nologo --noplugins --nocustomization --profiles-path "%SYNREX_QGIS_ROOT%\profiles" --profile synrex-r3 --code "%SYNREX_QGIS_ROOT%\qualify_qgis.py"
```

The helper captures actual application windows, queries complete provider data,
checks style/CRS, saves/reopens the project and closes through QgisApp after its
callback returns. The initial harness called immediate application quit and
crashed after successful checks; that failed exit and a CRS-assumption failure
are retained in the local attempts/evidence record. Final qualification requires
exit0; a written PASS JSON alone is insufficient.

For a48-byte viewing derivative (use a fresh receipt/output path):

```bash
python tools/qgis_copc_view.py --classified classified.laz --sidecar semantics.json \
  --staging viewer-staging.las --receipt staging.json
```

Then use the existing PDAL binary with this pipeline JSON:

```json
[
  {"type":"readers.las", "filename":"viewer-staging.las"},
  {"type":"writers.copc", "filename":"viewer.copc.laz", "forward":"all", "extra_dims":"all"}
]
```

```bat
"%QGIS_ROOT%\bin\pdal.exe" pipeline viewer-pipeline.json
```

```bash
python tools/qgis_copc_view.py --classified classified.laz --sidecar semantics.json \
  --copc viewer.copc.laz --receipt independently-verified-view.json
```

Open the result using the QGIS `copc` point-cloud provider and load the same R3
classification style. Retain the original sidecar and its original-order binding;
do not index that vector by COPC storage order. Use the added source index/semantic
attribute for correspondence. The local R3 package includes ready-to-open relative
projects, exact originals, viewing derivatives, notices and validation receipts.
Screenshot UI is QGIS/Qt third-party material; original presentation is CC-BY4.0
and underlying IGN survey information remains Etalab2.0.

[Actual COPC application receipt](../../evidence/unet_r3_qgis_copc_qualification.json):
three views,200,290 points, QGIS `copc` provider, exact per-point source index,
semantic ID and LAS class checks, actual rendering, EPSG:4326 transformation,
saved project reopening and process exit0 all PASS. Combined direct-LAZ/COPC
scope is ten unique scenes and1,062,717 points. This qualifies the viewing
workaround; it does not turn the original direct48-byte import failure into PASS.

For an independently verified directory of `*.copc.laz` and matching
`*-verified.json` receipts, the project inputs are prepared with:

```bash
python tools/prepare_qgis_showcase.py --data build/unet-r2/data \
  --qualified build/unet-r2/rtx/unet-r2-safe-qualified \
  --copc-views build/qgis-copc-views --out build/qgis-copc-project
```

Set `SYNREX_QGIS_ROOT` to that prepared directory and run the same application
command. Its `selection.json` explicitly selects the `copc` provider and retains
the original source CRS WKT. The automated helper validates the added point
index/semantic attributes against the original source-order sidecar for every
identified point. Metadata in the COPC view is explicitly outside the original
LAZ metadata-preservation guarantee.

The R3 release assembler can include both qualified projects while keeping caches,
profiles and installed software outside the archive:

```bash
python tools/prepare_unet_showcase.py --data build/unet-r2/data \
  --trained build/unet-r2/trained --qualified build/unet-r2/rtx/unet-r2-safe-qualified \
  --engine-package build/unet-r2/rtx/unet-r2-safe-qualified/unet.srxmodel \
  --synthetic build/unet/synthetic --media-manifest evidence/unet_r2_showcase_media.json \
  --qgis-direct build/r3/qgis/qualified --qgis-copc build/r3/qgis/copc-qualified \
  --out build/r3/showcase-r3
```

Use committed source and fresh output paths. The assembler requires actual PASS
application receipts and verifies harness, project and screenshot identities.
Open `qgis/direct/synrex-fractal-r2.qgz` for seven direct38-byte examples, or
`qgis/copc/synrex-fractal-r2.qgz` for the three48-byte viewing derivatives. Source
LAZ/classified LAZ/sidecar/binding remain separately included for independent checks.
The archive includes no QGIS profiles, EPT caches or SDK/application binaries.
